# 开工任务板（M0 启动批次）

> 依据：项目书 §10.2 开发实施分工 A–E ｜ 里程碑：M0（定名/工作区/数据模型/mock 数据）
> 状态约定：⬜ 未开始 ｜ 🔄 进行中 ｜ ✅ 完成
> 工程纪律（沿袭既往）：mock 优先、缓存幂等、改口径清缓存、脚本化验收、LLM 受限调用（max_tokens 上限 / 禁 reasoner / 单点缓存）。

## 0. 依赖与关键路径

```
B 策略知识库（纯知识工程，无依赖，可最先并行）
D 数据层（schema/mock）──关键路径起点，其余线都吃它的契约
   ├─ A 代价估算（吃 mock 台账 → 拆解/区间/口径假设）
   └─ C 话术-红线（吃 mock 策略 → 明确性校验）
E 移动端前端（吃 A/C/D 的 mock API 契约，响应式 Web）
```

- 建议推进顺序：**D →（A ‖ C ‖ B）→ E**；B 全程并行。
- M0 验收锚点：目录结构 + 数据迁移可跑 + mock 数据可查（本项目板第 T1–T3）。

## 1. 各线分工与首单任务

### 线 A · 代价估算引擎
目标：把"一句话需求"拆成任务清单 + 工时**保守区间** + 口径假设 + 风险/技术债标注（§8 防反噬口径：不给点值、只给区间、显式列假设）。
- 首单：读 D 线 mock 台账 → 产出"估算上下文契约"（字段草案：subtask/hours_low/hours_high/dependencies/risk/assumptions）。
- 依赖：T3（mock 数据）｜ 交付物：估算契约 + mock 拆解结果样例。

### 线 B · 策略知识库（纯知识工程，最先可跑）
目标：三类动机决策树（§2.3）＋ 汉弗莱策略库（§4.1）＋ 归因外置/中性动作/该接就接/明确性/拒绝债 文案库（§6）。
- 首单：把 §4.1 五条手段 + §6 新增的第 7/8/9 条护栏沉淀为**结构化策略 JSON**（每条含：触发条件/适用动机/话术模板/红线约束）。
- 依赖：无（读项目书即可）｜ 交付物：`data/strategy_lib.json`（含"明确度档位"与"高/低语境"两个开关）。

### 线 C · 话术-红线链路
目标：话术生成 + **双质检**（红线检测 §4.3 + 明确性校验 §6.8）→ 3 秒复述自检。
- 首单：定"话术产物结构"（text/version/step-holder/明确度档位/复述测试结论/redline 报告），接 B 线策略 JSON 做规则版生成。
- 依赖：T4（策略库）｜ 交付物：规则模式话术生成器（mock，无 LLM 也能跑通）。

### 线 D · 数据层
目标：关系型本地库 + 幂等种子（项目书附录 A 字段草案）。
- 首单：T1 迁移 001_init.sql（已落地）+ T2 seed_mock.py（已落地）→ 跑通"迁移可跑"。
- 交付物：`data/pushit.db` + 种子脚本 + DB 统计自检。

### 线 E · 移动端前端（响应式 Web，三端同源）
目标：5 Tab 页面地图（附录 B），先 mock 后接真接口。**平台拍板（2026-09-09）**：手机 / 桌面 / 网页三端同源，**重点手机端**；iOS 适配困难则先保 Android 可用，桌面浏览器为开发/演示主力（§9）。
- 首单：等 A/C 给出 mock 契约后，搭页面骨架 + 台账 Tab 静态 mock（“把消息贴进来”主入口 + 一键“记入/对齐”），先在桌面浏览器视口验收，再切手机视口（Android 优先）。
- 依赖：A/C 契约｜ 交付物：`frontend/index.html` + mock 层（浏览器可开的静态原型）。
